01

Quickstart

Two base URLs, one key. OpenAI-format clients use the base URL with /v1. Anthropic-format clients use the host without /v1, because their SDK appends /v1/messages itself.

Get a key

Contact us on @developnhackwithai to buy. We accept all payment methods as well as crypto. The Telegram bot sends your sk- key as soon as payment is confirmed.

Set the base URL and key

Pick the base URL that matches your client format. The key goes in the header Authorization: Bearer sk-..., or x-api-key as the Anthropic SDK sends it.

OpenAI format https://freeai.jembatanai.com/v1
Anthropic format https://freeai.jembatanai.com
shell 
export OPENAI_BASE_URL="https://freeai.jembatanai.com/v1"
export ANTHROPIC_BASE_URL="https://freeai.jembatanai.com"
The OpenAI SDK expects /v1 in the base URL; the Anthropic SDK adds it, so its base URL stops before it.

Send your first request

Copy one of the examples below and replace sk-... with your key.

python 
from openai import OpenAI

OPENAI_BASE_URL = "https://freeai.jembatanai.com/v1"

client = OpenAI(
    base_url=OPENAI_BASE_URL,
    api_key="sk-...",
)

reply = client.chat.completions.create(
    model="anthropic/claude-sonnet-5",
    messages=[{"role": "user", "content": "Hello!"}],
)

print(reply.choices[0].message.content)
The response is an ordinary ChatCompletion; nothing is wrapped.
python 
from anthropic import Anthropic

ANTHROPIC_BASE_URL = "https://freeai.jembatanai.com"

client = Anthropic(
    base_url=ANTHROPIC_BASE_URL,
    api_key="sk-...",
)

reply = client.messages.create(
    model="anthropic/claude-sonnet-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello!"}],
)

print(reply.content[0].text)
No /v1 here: the Anthropic SDK adds it.
curl 
curl https://freeai.jembatanai.com/v1/chat/completions \
  -H "Authorization: Bearer sk-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-5",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
Only the base URL and the key change. The rest is your code. Add "stream": true to stream the answer as Server-Sent Events.

02

Endpoints

Three endpoints take a conversation, and two read the state of your key. All of them use the same key.

API endpoints, their format, and the shape of requests and responses.
Endpoint Request and response
POST /v1/chat/completions OpenAI Chat Completions. The body carries model and messages, optionally stream, tools and max_tokens. The answer is in choices[0].message.
POST /v1/responses OpenAI Responses. model and input, optionally instructions, stream and tools. The answer is in output. This is the format Codex CLI uses.
POST /v1/messages Anthropic Messages. model, max_tokens and messages, optionally system, with the header anthropic-version. The answer is in content.
GET /v1/models Models this key can use. An OpenAI-format list: data holds id, owned_by and context_length for every model your key may use.
GET /v1/quota Quota left on this key. Your key's status, validity, balance and usage. See Check balance and validity.

03

Client setup

Every client below needs only the base URL, your key, and a model id from the catalogue. Any other client that accepts an OpenAI-compatible endpoint works the same way.

Claude Code uses the Anthropic format. Set these variables in your shell, then run claude. If Claude Code asks whether to use this API key, choose Yes.

shell 
export ANTHROPIC_BASE_URL="https://freeai.jembatanai.com"
export ANTHROPIC_API_KEY="sk-..."
export ANTHROPIC_MODEL="anthropic/claude-sonnet-5"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="deepseek/deepseek-v4.1-flash"

claude
Without ANTHROPIC_MODEL, Claude Code sends its own built-in model names, which are not in the catalogue, and gets a 403. Switch models inside a session with /model anthropic/claude-sonnet-5.

Codex CLI speaks only the Responses format. Add this provider to ~/.codex/config.toml, then set your key in OPENAI_API_KEY.

~/.codex/config.toml 
model = "deepseek/deepseek-v4.1-flash"
model_provider = "jembatanai"

[model_providers.jembatanai]
name = "Develop & Hack_With_Ai"
base_url = "https://freeai.jembatanai.com/v1"
env_key = "OPENAI_API_KEY"
wire_api = "responses"
Then export OPENAI_API_KEY="sk-..." and run codex. Codex refuses a provider without wire_api = "responses".

Cursor uses the OpenAI format through its own API key settings.

  1. Open the model settings — Cursor Settings, then Models.
  2. Enter the key and base URL — put your sk- key in OpenAI API Key, turn on Override OpenAI Base URL, and enter https://freeai.jembatanai.com/v1.
  3. Add a model — add an id from the catalogue, for example anthropic/claude-sonnet-5, then pick that model in chat.

Cline uses the OpenAI Compatible provider.

  1. Choose the provider — in the Cline settings, set API Provider to OpenAI Compatible.
  2. Enter the base URL and key — Base URL https://freeai.jembatanai.com/v1, and API Key set to your sk- key.
  3. Enter the Model ID — use an id from the catalogue, for example anthropic/claude-sonnet-5.

OpenCode takes an OpenAI-compatible provider through opencode.json in your project folder or in ~/.config/opencode/. Set your key in JEMBATANAI_API_KEY, then choose a model with the command /models.

opencode.json 
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "jembatanai": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Develop & Hack_With_Ai",
      "options": {
        "baseURL": "https://freeai.jembatanai.com/v1",
        "apiKey": "{env:JEMBATANAI_API_KEY}"
      },
      "models": {
        "anthropic/claude-sonnet-5": { "name": "Claude Sonnet 5" }
      }
    }
  }
}

Kilo Code adds this endpoint as a custom provider in the OpenAI Compatible format.

  1. Add a provider — open Settings, then Providers, and choose Custom provider.
  2. Enter the format, base URL, and key — Provider API OpenAI Compatible, Base URL https://freeai.jembatanai.com/v1, and API key set to your sk- key.
  3. Add a model — use an id from the catalogue, for example anthropic/claude-sonnet-5.

Models and access

Send the full id with its vendor prefix, exactly as returned by GET /v1/models, for example anthropic/claude-sonnet-5. Older short ids such as claude-sonnet-5 are still accepted, but these docs use the full id throughout.

  • The eight base models are on every key, the trial included.
  • Max and Ultron open the extension models in the catalogue; so do Token Plan and pay-per-use.
  • The frontier models are on Ultron, and on a pay-per-use balance at per-model dollar rates.
  • Models that accept image input are marked in the catalogue; send the image as the content part image_url.

05

Errors

Errors come back in the OpenAI format: an error object holding message, type, and code. The code stays stable, so your program should read code, not the message text.

401 · api_key_missing 
{
  "error": {
    "message": "API key tidak dikirim. Sertakan key ... atau `x-api-key`.",
    "type": "invalid_request_error",
    "code": "api_key_missing"
  }
}
HTTP status, error code, meaning, and what to do.
Status Code Meaning and what to do
400 wrong_api_host The request came in through another host. Use https://freeai.jembatanai.com/v1; your key stays valid.
401 api_key_missing The Authorization or x-api-key header was not sent. Check your client's environment variables.
401 api_key_not_recognized The key is mistyped, revoked, or was deleted after its term ended. Copy the key again from the bot.
401 · 403 api_key_expired The term has ended. Renew in the bot to keep the same key, before it is deleted during data cleanup.
401 api_key_inactive The key is inactive because its token balance ran out, its term ended, or an admin disabled it. Top up or renew in the bot.
402 payment_required The order is not fully paid yet. The key activates automatically once it is.
403 store_model_not_allowed A model this key is not entitled to, for example a plan model on a trial key, or an id that is not in the catalogue. Check GET /v1/models.
403 donor_model_not_allowed A frontier model on a key that is neither Ultron nor pay-per-use. Buy Ultron or a pay-per-use balance in the bot.
403 store_credit_exhausted The Token Plan balance ran out. Buy another Token Plan in the bot; the same key is active again at once.
402 payg_balance_empty The pay-per-use balance ran out. Top up in the bot; the same key works again at once.
403 api_key_suspended The key is suspended or revoked. Send an appeal with the first 8 characters of your key.
429 rpm_limit_exceeded A trial or older key hit its rate limit; the Pro, Max and Ultron plans have no rate limit. Wait for retry_after_seconds or the header Retry-After, then retry.
429 Too many concurrent requests Every parallel session on this key is busy and the queue timed out. Wait for the Retry-After.
503 key_lookup_failed A temporary fault while checking the key. Retry in a few seconds.
5xx Others A fault on the service side. Retry with a growing delay, and check the status page.

The most common problems

Claude Code gets a 403 straight away.
Set ANTHROPIC_MODEL to an id from the catalogue.
A 404 or an HTML page comes back.
The base URL is wrong: the OpenAI format needs /v1 at the end, the Anthropic SDK does not.
Codex refuses to read its configuration.
Codex only accepts wire_api = "responses".
A model you bought is not open yet.
Check GET /v1/models with the same key; that list is what the access gate uses.

Check balance and validity

GET /v1/quota answers about the key that sends it and nothing else, with no other parameter. It carries: status and plan, validity, the token or dollar balance left, usage today, over the last 7 days and over the last 30 days, and a warn or throttle flag.

curl 
curl https://freeai.jembatanai.com/v1/quota \
  -H "Authorization: Bearer sk-..."

# example response, shortened
{
  "object": "quota",
  "key": "sk-xxxxx...xxxx",
  "status": "active",
  "plan": "monthly",
  "valid_until": "2026-12-11T00:00:00Z",
  "balance": { "tokens_left": 482000 },
  "usage": { "today": 18000, "last_7_days": 64000 }
}
